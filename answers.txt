Лабораторная работа №19. Ответы на контрольные вопросы

1. Основные принципы и преимущества CI/CD.
Изменения регулярно отправляются в общий репозиторий. После изменения кода
автоматически выполняются тесты и сборка. Ошибку можно обнаружить сразу,
пока изменённый участок небольшой. Одинаковые команды уменьшают число
ручных ошибок и позволяют повторить проверку на другом компьютере.
CD добавляет доставку или развёртывание проверенной версии приложения.

2. Разница между CI, Continuous Delivery и Continuous Deployment.
CI — непрерывная интеграция: частое объединение изменений, тесты и сборка.
Continuous Delivery — проверенная версия готова к выпуску, но запуск
развёртывания в рабочей среде подтверждает человек.
Continuous Deployment — прошедшая проверки версия развёртывается автоматически.
В этой работе push в main запускает тесты, сборку и облачный деплой.

3. Роль GitHub Actions и компоненты workflow.yml.
GitHub Actions выполняет автоматические действия по событиям репозитория.
Файл находится в .github/workflows/deploy.yml.
name — название; on — события запуска; jobs — задания; runs-on — среда
выполнения; steps — шаги; uses — готовое действие; run — команда;
env — переменные окружения; permissions — разрешения временного токена.
В работе checkout получает код, setup-node выбирает Node.js, npm ci ставит
зависимости по lock-файлу, Jest проверяет код, Docker собирает образ.
Образ отправляется в GHCR, затем Northflank развёртывает его в облаке.

4. Подготовка NestJS к облаку.
Сервер получает порт из PORT, при отсутствии использует 3000. HOST=0.0.0.0
позволяет принимать соединения снаружи контейнера. npm run build компилирует
TypeScript в dist. Procfile содержит web: node dist/main.js.
В Docker используется CMD с этой же командой. Northflank запускает Docker-образ;
Procfile оставлен для выполнения задания и совместимости с PaaS, читающими его.
Подключение к PostgreSQL передаётся через DATABASE_URL, секрет JWT — через
JWT_SECRET. Приложение проверяет БД в /health. Этот маршрут также показывает
SHA версии, поэтому CI проверяет фактическую публикацию нового образа.
В учебном проекте TypeORM synchronize=true создаёт таблицы автоматически.
Для реального приложения со значимыми данными нужны контролируемые миграции.

5. Зачем нужны secrets.
Пароль или токен в репозитории может прочитать другой человек; даже удаление
строки не убирает её из истории Git. Поэтому .env исключён через .gitignore,
а из Docker-контекста — через .dockerignore.
NORTHFLANK_API_TOKEN хранится в GitHub Actions Secrets и используется только при
деплое. Это токен для деплоя данного проекта, а не пароль от аккаунта.
GITHUB_TOKEN выдаётся GitHub автоматически; для отправки образа ему разрешён
packages: write. DATABASE_URL и JWT_SECRET находятся в переменных Northflank.
PUBLIC_URL, NORTHFLANK_PROJECT и NORTHFLANK_SERVICE не являются секретами: это адрес и ID сервиса.

Почему тесты до сборки критичны для CI?
Если изменение нарушило поведение, Jest возвращает ненулевой код выхода.
Следующие обычные шаги GitHub Actions не выполняются: сломанный образ не
публикуется и не попадает в облако. Шаг очистки с always() может выполниться
после ошибки, но он только останавливает тестовые контейнеры.
Тесты полезны, только если проверяют значимое поведение. Здесь проверяются
порт, пароль, JWT, роли, доступ к задачам и готовность базы данных.
