Показ лабораторной №19 по строкам задания

За 5–10 минут до защиты: npm.cmd run cloud:start.
Открыть lab9 в VS Code, успешный deploy.yml в GitHub Actions и облачный /health.
Для команд test/build нужны установленные node_modules (npm.cmd ci).
Для облачного показа Docker Desktop на Windows не нужен.
Публичные ссылки и доказательства — Проверка.txt.
Не запускать полный deploy во время короткого показа: используйте его журнал.

ЗАДАНИЕ 1. «Настроить прослушивание порта, используя process.env.PORT
или дефолтное значение 3000».
Показать src/main.ts: getPort(process.env.PORT), app.listen(port,...).
Открыть src/config/port.ts: Number(value || 3000) и проверка диапазона.
Сказать: «Порт передаёт облачная платформа. Если PORT не задан, используется
3000. Адрес 0.0.0.0 позволяет подключаться к серверу извне контейнера».
Открыть tests/port.spec.ts: тесты стандартного, назначенного и неверного порта.
В E2E отдельно проверен реальный контейнер с PORT=31919.
3006 — порт Windows, перенаправленный Compose на порт 3000 контейнера.

«Создать Procfile в корне проекта с командой для запуска продакшн-версии».
Открыть Procfile: web: node dist/main.js.
Сказать: «Запускается уже собранный JavaScript из dist».
Docker запускает CMD. Procfile подготовлен по условию и подходит для
совместимых PaaS; Codespaces запускает именно Docker-контейнер.

«Подготовить package.json для продакшн-сборки (npm run build)».
Открыть package.json, показать build: nest build и start:prod.
Выполнить npm.cmd run build. Показать появившийся dist/main.js.

ЗАДАНИЕ 2. «Создать файл .github/workflows/deploy.yml».
Открыть этот файл и объяснить: «GitHub ищет workflow в этой папке».

«Настроить workflow, который запускается при push в ветку main».
Показать on -> push -> branches: [main].
pull_request запускает проверки, но не публикацию и деплой.
workflow_dispatch позволяет повторить запуск кнопкой Run workflow.

«Получение исходного кода; настройка среды Node.js».
Показать actions/checkout и actions/setup-node с версией Node.js.

«Установка зависимостей; сборка приложения».
Показать npm ci и npm run build.
Сказать: «npm ci устанавливает точные версии из lock-файла, поэтому
результат воспроизводим. По смыслу это установка зависимостей npm для CI».

«Сборка Docker-образа из оптимизированного Dockerfile из ЛР №18».
Показать два FROM в Dockerfile. В первом этапе происходит сборка,
во второй копируются только dist и производственные node_modules.
Показать шаг docker build в Actions и его успешный журнал.

«Отправка образа в контейнерный реестр».
Показать шаги входа в ghcr.io и docker push, затем пакет GitHub Packages.
Сказать: «У образа два тега: SHA коммита для точной версии и latest».
Вход использует временный GITHUB_TOKEN, пароль в YAML не хранится.

«Развёртывание приложения на облачной платформе».
Показать фактический адрес и облачный статус из Проверка.txt.
Открыть /health: должны быть status=ok, database=connected,
version=SHA коммита. Сравнить SHA с запуском Actions.
Открыть https://github.com/codespaces: показать среду veb-lab19-cicd.
Сказать: «Для учебной работы облаком служит Codespaces. В нём Docker
запускает образ, который прошёл тесты и был отправлен в GHCR. PostgreSQL
работает отдельным контейнером, а его файлы сохраняются между включениями».
Показать успешные Deploy tested image to Codespaces и Verify deployed version
and database. SHA в /health совпадает с SHA проверенного запуска.
Это учебная среда с остановкой при простое, поэтому я включаю её перед показом.
Для живой демонстрации регистрации/JWT/ролей: npm.cmd run cloud:demo.
В журнале этого workflow видны реальные ответы API из облака.

ЗАДАНИЕ 3. «Добавить шаг для запуска тестов после установки зависимостей,
но до сборки приложения».
В deploy.yml показать порядок: npm ci -> npm run test -> npm run build.
В терминале npm.cmd run test: должны пройти 29 тестов.
Показать tests/auth.spec.ts: неправильный пароль отклоняется;
tests/access.spec.ts: пользователь не читает чужую задачу.

«Пайплайн останавливается и сигнализирует об ошибке, если тесты не пройдены».
Показать отчёт отрицательной проверки в Проверка.txt. В отдельной копии
порт по умолчанию изменён на 3001; два теста обнаружили ошибку, конвейер
остановился на test, сборка не запускалась. Основной проект не ломался.
Объяснить: «Jest возвращает ненулевой код выхода. GitHub Actions помечает
шаг как failed и пропускает следующие обычные шаги».

«Объяснить, почему этот шаг критически важен для CI».
Сказать: «Ошибка находится до публикации. Неработающая версия не попадёт
в реестр и облако. Тесты выполняются автоматически при каждом push».

Дополнительно: npm.cmd run demo показывает, что после изменений
приложение по-прежнему регистрирует пользователей, выдаёт JWT и проверяет роли.
Ответы на контрольные вопросы — answers.txt.

После защиты: npm.cmd run cloud:stop. Файлы и данные БД сохраняются.
